# Monoxide: Scale Out Blockchain with Asynchronous Consensus Zones

### 主要内容
文献《Monoxide: Scale Out Blockchains with Asynchronous Consensus Zones》的核心内容主要围绕区块链的扩展性和性能提升。

传统的区块链结构包含一个主链，整个链的状态由一个账簿记录，一个主要缺点是每个节点都需要复制大量的相同信息，这不仅消耗大量的资源，还影响运算速度。

为了解决这个问题，这篇文献提出了一种基于异步共识区的区块链扩展方法。这种方法将整个系统划分为多个内部结构相同的共识组，每个共识组都是一个单链系统，依靠分区域技术，将网络通讯、存储（合约计算）、状态表达和交易验证这四个方面的工作量全部进行分片处理，并且它们各自独立运行，互不影响。这种设计允许各共识组并行、异步并独立地工作，各区域独立验证。同时，每个共识组能够独立完成共识、校验和执行交易，以及维护组内用户的状态和历史记录，大大提高了系统的整体性能。

基于此，文献提出了一个亮点设计--最终原子性，即针对于收款人付款人分别在不同分片区域的交易，系统允许先执行付款人的提款操作，而收款人的存款操作可以延后执行，依赖共识机制最终一定会实现存款操作。这个设计使得系统可以更快的响应用户交易，即使跨区交易会增加一定的开销，但仍可以尽可能的维持系统吞吐量的增加趋势。

为了有效抵御分区域跨链结构中可能出现的算力分散问题文献还提出了一种算力放大机制chu-ko-nu机制。通过这种机制，物理算力（计算哈希的速度）可以被放大为n倍对应的有效算力（实际出块的速度），并且这种放大的算力必须平均分配到各个共识组。这种机制确保了即使部分共识组受到攻击，系统的整体安全性也不会受到影响。

### 研究方法
1.文献综述:通过对现有的区块链扩展性和性能提升方案进行了综述，分析了它们的优缺点，从而引出了自己的研究动机和目标。
2.系统设计:提出了对Monoxide系统的设计方案，包括异步共识区的划分、全分片技术的实现、算力放大机制的设计等。通过系统设计的阐述，读者可以清楚地了解该系统的核心思想和工作原理。
3.理论分析:通过数学模型和算法描述，对Monoxide系统的性能、安全性和可扩展性进行了理论分析，证明了该系统相比传统区块链具有更高的吞吐量和更低的延迟，并且能够有效抵御特定共识组的攻击。
4.实验验证:通过实验验证了Monoxide系统的实际效果，包括不同共识组数下的性能测试、安全性测试等，以验证系统设计的正确性和有效性，如测试在什么样的块大小和块创建间隔配置下能够平衡好高吞吐量以及较低的孤儿率。
5.对比分析:将Monoxide系统与其他区块链扩展方案进行了对比分析，展示了该系统在性能、安全性和可扩展性方面的优势。

### 优点
1.扩展性:Monoxide提出的系统通过将区块链划分为多个独立的共识组，实现了链的水平扩展。每个共识组可以独立运行和达成共识，从而大大提高了系统的整体吞吐量和处理速度。
2.性能提升:由于各个共识组可以并行工作，系统可以同时处理更多的交易和请求。这种并行处理能力使得Monoxide系统能够应对高并发场景，吞吐量显著提升，有效缓解了传统区块链中的性能瓶颈。
3.资源利用率:通过分片技术，Monoxide将网络通信、存储（合约计算）、状态表达和交易归档等工作分配到各个共识组，使得每个节点只需维护与其相关的部分信息，而不再需要存储整个网络的状态信息，这大大减少了不必要的资源消耗，减轻了系统各个节点的工作负载，提高了系统的资源利用率。
4.安全性增强:通过chu-ko-nu机制，可以抵御特定共识组的攻击。避免了分区域算力也被均分的情况，确保了51%攻击的算力难度。
5.灵活性: 允许根据实际需求调整共识组的数量和配置，从而灵活应对不同的应用场景。

### 缺点
1.复杂性:由于系统涉及多个共识组并行运行和交互，影响系统稳定性和安全性的因素增多，随着区域的增加，实现和维护这样的系统可能相对越来越复杂。
2.开销:在各个共识组之间需要进行信息同步和交互。由于系统提出的对于链块Batch-chaining-block改进，随着区域数量的增加，一定会进一步导致一定的通信开销以及存储开销。
3.一致性问题:虽然异步共识机制降低了各个共识组之间的依赖，但不同共识组之间的状态同步和最终一致性需要得到保证，否则可能导致数据不—致的情况。
4.监管挑战:由于Monoxide的设计允许更多的并发性和匿名性，可能给监管机构带来更大的挑战。
5.文献作者提出的不足：单地址空间及矿工的激励和费用有待优化。

### 疑问（文献中存在的不懂得地方）
1.为什么会存在跨区交易，也就是系统分组分区域是依照什么来分的。初步设想是根据用户的地址空间成单或成组进行分区域，但是未经过进一步验证。
2.关于块或交易验证部分如何进行重建。由于分叉存在产生的一个可用块变成未解决/孤儿块后其后的已确认的块的处理，系统提出了依据merkle树执行自创世纪块以来的所有记录操作来重建区块来维持一致性。

### 展望（基于文献可以进一步进行的工作）
1.性能优化:可以进一步思考如何减少通信延迟，缩减由于分区域所带来的开销（通信、存储），以及优化采矿算法等。对于区块链系统的扩展性是否有其他的更优秀的方案解决。
2.安全性增强:在系统提出的chu-ko-nu机制基础上进一步引入新的加密技术或安全协议，来提高系统的安全性。
3.实际应用落地:可以尝试如何将Monoxide等扩展区块链技术和实际系统相融合。
